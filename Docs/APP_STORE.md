Screenshots are generated by driving the **real app** (`ScreenshotTests`), so
the store can never show something the app doesn't do.

```bash
Scripts/screenshots.sh
```

That captures nine states at iPhone 17 Pro resolution (1206×2622) and writes
them to `Artifacts/screenshots/`.

Apple currently requires one 6.9" iPhone set; other sizes are optional and are
scaled from it. To also produce the 6.5" set, re-run with a different simulator:

## Steps you need to take

1. **Enrol / sign in** at [developer.apple.com](https://developer.apple.com) —
   the Apple Developer Program is $99/year.

2. **Signing is already configured** (team `76CS9U9VX6`, automatic, applied to
   all three targets). Nothing to do unless you're publishing from a different
   team.

3. **Bundle ID is already set** to `com.amirjabbari.ninetynineapp`, with team
   `76CS9U9VX6` and automatic signing. Note this **cannot be changed after the
   first submission** — if the `app` suffix wasn't deliberate, change it now.

4. **Register the app** in
   [App Store Connect](https://appstoreconnect.apple.com) → *My Apps* → **+** →
   *New App*. Use the name and bundle ID above.

5. **Archive and upload:**
   ```bash
   Scripts/archive.sh
   ```
   Then in Xcode: *Window → Organizer → Distribute App → App Store Connect*.
   (Or upload the exported `.ipa` with Transporter.)

6. **Fill in the listing** using the copy above, and upload the screenshots from
   `Artifacts/screenshots/`. Set the support and privacy policy URLs to your
   GitHub repo (see the URLs above).

7. **Submit for review.** First reviews typically take 24–48 hours.

## Likely review notes, pre-empted

Rejections for a game like this usually come from one of these. All are already
handled:

- **Guideline 2.1 — incomplete information.** Nothing is stubbed; every button
  works and the game plays to a genuine conclusion. Verified by a UI test that
  plays a full game.
- **Guideline 5.1.1 — privacy.** Nothing is collected, the privacy manifest says
  so, and the app has no network code to contradict it.
- **Guideline 2.3.1 — hidden features.** The two `-uitest-*` launch arguments
  only reset or seed local `UserDefaults`, are inert without being passed on the
  command line, and unlock nothing. They're for the automated tests.
- **Guideline 4.7 / gambling.** There is no wagering, currency, chips, or prize
  of any kind. It's a shedding card game.
- **Guideline 1.2 — user-generated content.** There is none.
- **Design 4.0 — iPad.** The app builds for iPad, is portrait-only (declared in
  `Info.plist`), and a full game has been played through on a 13" iPad Pro via
  the automated UI test.

## Things worth deciding before you ship

- **iPad** was tested, not assumed: the full-game UI test passes on a 13" iPad
  Pro, and the layout holds content to a phone-shaped measure (540pt) centred on
  screen, with the gauge and fan scaling to the height available. It reads as a
  deliberate composition rather than a stretched phone. It is still, honestly, a
  phone game shown on a large screen — a genuine iPad design (landscape, a real
  table with seats around it) would be a worthwhile 1.1. If you'd rather not
  ship iPad at all, set `TARGETED_DEVICE_FAMILY` to `1`; that's a legitimate and
  common choice.
- **Localisation** is English only. `LOCALIZATION_PREFERS_STRING_CATALOGS` is on
  and `SWIFT_EMIT_LOC_STRINGS` is set, so adding languages later is
  straightforward.
